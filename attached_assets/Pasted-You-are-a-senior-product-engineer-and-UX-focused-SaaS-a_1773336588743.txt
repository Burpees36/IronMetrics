You are a senior product engineer and UX-focused SaaS architect. Upgrade the existing Workouts feature into a production-ready Programming Hub for a gym operating system that is intended to replace Wodify.

CONTEXT
The current Workouts page acts like a digital whiteboard. Right now coaches can create a workout with:
- name
- type
- date
- description
- movements

The backend already supports:
- creating workouts
- retrieving workouts
- logging member results per workout
- retrieving results per workout

The current UX is too basic and not ready for real gym use.

YOUR TASK
Redesign and implement this feature so it becomes the primary place where gym owners and coaches create, manage, and publish daily programming for their gym, while members can view the programming but cannot edit it.

CORE PRODUCT REQUIREMENTS

1. TURN “WORKOUTS” INTO A TRUE DAILY PROGRAMMING HUB
Gym owners/coaches should be able to create a full day of programming, not just one flat workout card.

A single day should support multiple sections such as:
- Warm-Up
- Mobility / Prep
- Skill
- Strength
- Conditioning / Metcon
- Accessory
- Cool Down
- Notes / Coach Brief
- Custom Section

Each section should support:
- section title
- section type/category
- optional time cap or target duration
- optional objective/intended stimulus
- rich text / structured instructions
- optional movement list
- optional scaling notes
- optional coach notes
- optional member-facing notes
- optional order index so sections display in the correct sequence

Important:
- A “day” is the main programming container
- A day contains multiple ordered sections
- A gym may have one programming track per day initially, but structure the code so multiple tracks could be supported later (ex: group class, competitor, foundations, endurance)

2. IMPROVE UX DRAMATICALLY
The current modal is too primitive. Replace it with a production-quality workflow.

New creation/edit UX should include:
- a proper “Create Programming Day” flow, preferably a slide-over panel or dedicated page instead of a cramped modal
- clear separation between day-level details and section-level details
- drag-and-drop or move up/down reordering for sections
- “Add Section” buttons with quick templates (Warm-Up, Strength, Conditioning, etc.)
- autosave draft behavior or clear unsaved-changes protection
- form validation with useful inline feedback
- better date handling
- mobile-friendly layout
- polished visual hierarchy
- section cards with icons/labels
- preview mode before publish
- duplicate/copy previous day functionality
- save as draft / publish workflow

The workflow should feel like a real coaching tool, not a generic CRUD form.

3. PERMISSIONS / ROLES
Implement clear role behavior:
- Owners/Admins: full create/edit/delete/publish access
- Coaches: create/edit programming if they have programming permissions
- Front desk / members: view only
- Members: can only view published programming for their gym; absolutely no editing access

Ensure all backend authorization is enforced server-side, not just hidden in the UI.

4. MEMBER VIEW
Create a clean member-facing version of the daily programming.

Members should be able to:
- view today’s workout
- view upcoming programmed days
- expand sections
- see movement details
- see notes meant for members
- log their result where applicable if result logging already exists
- view results/leaderboard if enabled for that section/day

Members should NOT see:
- internal coach-only notes
- edit controls
- admin management actions
- draft/unpublished programming

5. COACH / OWNER VIEW
The staff version of the programming hub should include:
- today / week view
- clear published/draft state
- number of results logged
- edit programming
- duplicate day
- archive/delete day
- quick jump to previous/next dates
- optional “coach notes” block only visible to staff
- section-by-section management
- workout result activity summary

6. DATA MODEL / ARCHITECTURE
Refactor the data model so it supports production use.

Implement a structure like:
- Programming Day / Workout Day
  - gym_id
  - date
  - title or optional theme
  - status: draft / published / archived
  - audience/track placeholder for future extensibility
  - public notes
  - private coach notes
  - created_by / updated_by
  - timestamps
- Programming Sections
  - parent day id
  - ordered position
  - section type
  - title
  - instructions/content
  - duration/time cap
  - intended stimulus
  - movements
  - scaling notes
  - coach-only notes
  - member-facing notes
  - result_tracking_enabled boolean
  - timestamps

Keep backward compatibility in mind if existing workout records exist. Either:
- migrate existing flat workouts into a default single section model
or
- preserve legacy reads while moving new records to the new structure

Choose the safest migration path and implement it cleanly.

7. RESULTS / LEADERBOARD READINESS
The backend already supports result logging per workout. Upgrade the structure so result logging can map properly to the day or the main scored section.

Requirements:
- support one section being designated as the scored/result-tracked section
- keep room for multiple scored sections later
- show count of logged results on the day card
- create hooks for future leaderboard UI
- do not break existing result logging if possible

8. PAGE REDESIGN
Redesign the Workouts page so it feels like part of a premium gym operating system.

Desired page experience:
- Header with date navigation and primary CTA
- Toggle between Today / Week / Calendar or List
- Daily cards or agenda layout
- Strong visual distinction between draft and published
- Clear section previews on each day card
- Better empty states
- Better onboarding states for new gyms
- Cleaner card layout, spacing, and typography
- Remove “toy app” feel completely

9. NICE-TO-HAVE IF FEASIBLE
If reasonably achievable within this sprint, include:
- duplicate previous day
- recurring templates
- save section as reusable template
- “copy to another date”
- collapsible sections
- print-friendly whiteboard view
- coach-only briefing block
- sticky “Today” quick access

10. DO NOT OVERBUILD
This should feel polished and production-ready, but not bloated.
Focus on:
- strong data structure
- excellent UX
- role-safe access
- staff/member separation
- future extensibility

IMPLEMENTATION EXPECTATIONS

A. FRONTEND
Build/upgrade:
- staff programming hub page
- member programming view
- create/edit programming experience
- section builder UI
- day cards/list/week display
- publish/draft controls
- empty/loading/error states

B. BACKEND
Build/upgrade:
- schema changes
- migrations
- CRUD endpoints for programming day + sections
- publish/unpublish endpoints if needed
- secure role checks
- result-tracking compatibility
- gym-scoped queries only

C. UX QUALITY
Use best practices:
- clean spacing
- consistent typography
- intuitive labels
- minimal friction
- polished action states
- confirmation dialogs for destructive actions
- toasts for success/error
- robust validation

D. DELIVERABLE FORMAT
When complete, provide:
1. Summary of what changed
2. Files changed and why
3. Schema/API changes
4. UX improvements made
5. Role/access rules enforced
6. Any migration or backward-compatibility notes
7. Remaining future enhancements

SUCCESS CRITERIA
This is successful when:
- a gym owner can create a full day of programming with multiple sections
- a coach can manage daily class programming efficiently
- a member can view only the published version of that day
- the UX feels polished and premium
- the system is clearly ready to serve as a real gym’s daily programming hub
- the implementation is extensible enough for future templates, leaderboards, and multi-track programming

IMPORTANT PRODUCT DIRECTION
Design this like the core daily programming system of a serious gym management platform replacing Wodify — not like a generic notes app or a simple workout CRUD page.
Favor clarity, coaching workflow, and operational usefulness.
