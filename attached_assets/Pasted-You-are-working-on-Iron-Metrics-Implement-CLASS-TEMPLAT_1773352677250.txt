You are working on Iron Metrics. Implement CLASS TEMPLATES + COPY LAST WEEK ONLY.

Do not work on onboarding, billing recovery, payment failure emails, update card flow, forecasting, communication hub, waitlists, or member self-service.
Keep this sprint tightly scoped to solving weekly class scheduling friction for real gym operators.

OBJECTIVE
Eliminate the need to recreate the same class schedule manually every week by adding:
1. Weekly class templates
2. Copy last week / copy previous schedule actions

WHY THIS EXISTS
The analysis identified this as a Tier 1 production need and one of the biggest operational pain points. Owners will not forgive having to rebuild the same schedule manually every week. This sprint should make scheduling dramatically faster and more professional.

SUCCESS CRITERIA
- Staff can save a reusable weekly schedule template.
- Staff can apply a weekly template to a selected week with one action.
- Staff can copy last week’s schedule into a future week with one action.
- Duplicate/overlapping classes are handled safely.
- The UI makes the action feel low-risk and understandable.
- A real gym owner can set up next week’s schedule in minutes instead of rebuilding it class by class.

FEATURE SET

PART 1 — COPY LAST WEEK
Add a one-click scheduling shortcut from the schedule page.

Requirements:
- Add a clear “Copy Last Week” or equivalent action in the schedule UI
- Let the user choose a target week
- Copy classes from the immediately previous week into the selected week
- Preserve important class details such as:
  - class name
  - day of week
  - time
  - duration if supported
  - coach assignment if valid
  - capacity
  - class type/category if supported
  - location if supported
- Do not copy attendance/check-ins/enrollments
- Do not copy historical member state
- Shift dates correctly to the new week
- Show a confirmation preview or summary before applying

PART 2 — WEEKLY TEMPLATES
Add reusable schedule templates for recurring weekly structure.

Requirements:
- Allow staff to save the current week’s schedule as a named template
- Allow creation of a template from scratch if practical, but saving from existing week is the priority
- A template should represent recurring weekly classes by weekday/time, not specific calendar dates
- Allow applying a template to any selected week
- When applied, generate real classes for that week
- Make template names human-friendly, e.g.:
  - Regular Week
  - Summer Schedule
  - Open Prep Week
  - Holiday Lite Schedule

PART 3 — SAFE APPLY / DUPLICATE HANDLING
Avoid accidental messy schedules.

Requirements:
- Before applying a template or copied week, detect possible conflicts:
  - same day/time duplicates
  - overlapping classes if the product treats those as invalid
- Show the user what will happen before committing
- For Day 3, support a safe default strategy:
  - skip exact duplicates
  - create only non-conflicting classes
- Clearly summarize:
  - classes to be created
  - duplicates skipped
  - conflicts needing attention
- Do not silently duplicate a whole week

PART 4 — TEMPLATE MANAGEMENT
Let staff manage templates cleanly.

Requirements:
- Add a simple template management area in or near the schedule page
- Staff can:
  - create/save template
  - rename template
  - apply template
  - delete template
  - view template contents
- Keep this lightweight and intuitive
- Do not build a huge admin subsystem

PART 5 — EMPTY STATE + FIRST USE
Make it discoverable and helpful.

Requirements:
- If a gym has no future schedule, show strong actions such as:
  - Create Class
  - Copy Last Week
  - Apply Template
- If no templates exist yet, guide the user to save the current week as their first template
- Add friendly helper text explaining the value

DATA MODEL / BACKEND REQUIREMENTS
- Add the minimum schema necessary to store weekly class templates cleanly
- Template records should be gym-scoped
- Template application must create real upcoming class records for the selected week
- Respect Day 1 gym access protections
- Validate all write actions on the backend
- Reuse existing class creation logic where possible instead of duplicating it

MAPPING / COPY LOGIC REQUIREMENTS
- Preserve class metadata where appropriate
- If a coach from the source schedule is no longer valid for the gym or unavailable in current data model, fail gracefully or leave unassigned with a warning
- Time and weekday mapping must be deterministic
- Timezone handling must be correct
- Avoid date-as-text mistakes if those fields still exist; use the safest consistent handling available in the current architecture

UX REQUIREMENTS
- Make this feel premium and operationally useful
- Add preview before commit
- Strong confirmation language
- Friendly error states
- Clean result summary after apply:
  - created
  - skipped as duplicates
  - conflicts
- Use the app’s existing premium visual language
- Optimize for a stressed gym owner doing next week’s schedule quickly

OUT OF SCOPE
Do not build:
- Waitlist system
- Member notifications for schedule changes
- Recurring exceptions engine
- Holiday auto-adjustments
- Staff availability planner
- Coach payroll logic
- Drag-and-drop calendar rebuild
- Advanced recurring rules beyond weekly template application

TESTING / VALIDATION
After implementation, verify:
1. A user can copy last week into a target week successfully.
2. Attendance and enrollments are not copied.
3. A user can save a week as a template.
4. A saved template can be applied to a future week.
5. Duplicate classes are skipped safely.
6. Another gym’s templates/classes cannot be accessed or modified.
7. The schedule page now makes weekly setup meaningfully faster.
